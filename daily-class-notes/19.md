## OIDC based cloud authentication
* OIDC stands for , OpenID connect.
* Its an identity protocol that allow github actions to authenticate to cloud providers without storing long lived credentials.
* The old way
    * GCP > IAM SVC Account > Key (.json) will have expiry > long lived keys > svc account > github actions > key > secret
* the OIDC way - short lived tokens:
```
Workflow run -> github generated a short lived OIDC token. 
    -> token is sent to cloud provider (AWS/GCP/Azure)
    -> Cloud provider will verify if the token is coming from your github repo 
    -> Cloud provider issues a temp access token.
    -> workflow uses that token to access cloud resources. 
    -> token will expire when the workflow finishes. 
    -> no credentilas are stored anywhere . 
```
* we need to configure OIDC setup before the workflow runs. 
* permissions:
    * to use OIDC the workflow job mush have permissions to request IODC token from github 
    * this permissions can be implemented at the workflow level, or job level as well. 
```yaml
permission: 
    id-token: write     # REQUIRED , allow the job to request oidc token
    contends: read      # read the repo code 
```

Workload Identity allows your workloads to access Google Cloud without Service Account keys. There are 4 steps to setting up a workload identity:

1. Create a workload identity pool
The pool organizes and manages external identities. IAM lets you grant access to identities in the pool.
2. Connect an identity provider
Add either AWS or OpenID Connect (OIDC) providers to your pool.
3. Configure provider mapping
Set attributes and claims from providers to show up in IAM.
4. Grant access
Use a service account to allow pool identities to access resources in Google Cloud.
